# Components

Astro components shared across the site. **One component per content type** — `BlogCard` is the only card; don't introduce a generic `<Card>`. See [`../../STYLE_GUIDE.md`](../../STYLE_GUIDE.md) for design rules (colors, typography, cards, motion); this file is for component-specific usage.

## Sidecar docs

Every `*.astro` here has a sibling `*.md` sidecar documenting its purpose, props, slots, owned i18n keys, and gotchas. The sidecar describes the **local** component — props always come from the component's own `interface Props`, never from upstream. When you add or change a component, update its sidecar in the same commit. A build-time check (`scripts/check-component-docs.mjs`, run in `prebuild`) fails if a sidecar is missing or malformed; run `pnpm sync:component-catalog` to regenerate the catalog below.

## Conventions

- **Astro over React.** Only reach for React when interactivity genuinely demands it.
- **No hex literals.** Tailwind utility classes that map to `@theme` tokens in `src/styles/global.css`.
- **Icons:** `@lucide/astro` only. No emojis.
- **i18n:** `useTranslations(locale)` from `~/i18n`. A new string means updating both `src/i18n/de.json` and `src/i18n/en.json` in the same commit.
- **Images:** `<Image>` from `astro:assets`. Alt text is mandatory (ESLint enforces `jsx-a11y/alt-text` as error).
